BMC Bioinformatics paper results from this `manuscript` branch.

### Greedy + 2-OPT

#### Step A — candidate pool (input to BarLay)

Before placement, a **candidate pool of 150,000 unique 36-nt barcodes** was
generated with the same procedure as in the companion benchmarking paper
([Poma-Soto et al. 2026](https://github.com/OncoRNALab/BarcodeCalling_benchmark)):

1. Draw 36-nt DNA sequences uniformly at random.
2. Keep a sequence only if it is unique in the pool so far **and**
   - maximum homopolymer run ≤ 3 nt, and
   - G content ≤ 25% (≤ 9 G in 36 nt).
3. Repeat until 150,000 sequences pass.

This pool is **not** committed in the repo (large; regenerable). A minimal
regenerator matching those filters:

```bash
python3 - <<'PY'
import random
from pathlib import Path

def ok(seq: str) -> bool:
    if seq.count("G") > 9:  # ≤ 25%
        return False
    run = best = 1
    for a, b in zip(seq, seq[1:]):
        run = run + 1 if a == b else 1
        best = max(best, run)
    return best <= 3

random.seed(42)  # choose any seed; paper pool used an independent draw
need, alphabet, seen, out = 150_000, "ACGT", set(), []
while len(out) < need:
    s = "".join(random.choices(alphabet, k=36))
    if s in seen or not ok(s):
        continue
    seen.add(s)
    out.append(s)
Path("barcodes_150k_36nt.txt").write_text("\n".join(out) + "\n")
print(f"wrote {len(out)} barcodes → barcodes_150k_36nt.txt")
PY
```

The same filters can be applied via the RandomBarcodes / Press barcode-generation
scripts shipped inside
[BarcodeCalling_benchmark](https://github.com/OncoRNALab/BarcodeCalling_benchmark)
(`bin/press/scripts/1_BarcodeGen_split.py`); set `N: 150000`, `M: 36`,
`homomax: 3`, and a G limit of 25% to match the manuscript wording.

A **second, independent** pool of 150,000 barcodes was generated with the same
procedure for Greedy decoys (not used as BarLay input). Decoys were subsampled
from that pool; the committed source used by `decoys/scripts/make_greedy_decoys.py`
is `data/decoy_layouts/barcodes/1in1/greedy_decoybar_1in1_column_major.txt`
(85,305 sequences from that second pool).

#### Step B — placement with BarLay

The first 150k pool was the input library for
[BarLay](https://github.com/Jatzkowski/BarLay) (external repository; commit
`e22a877603` as cited in the paper). BarLay ran greedy placement + 2-OPT local
search with default settings on NVIDIA A100 GPUs at the VSC and placed
**85,305** barcodes on the 235 × 363 grid. The printed layout is committed in
`data/1in1/`:

- `layout_235x363_randombarcodes_opt_coords.csv`
- `layout_235x363_randombarcodes_opt.txt`

## 4. Simulated and real FASTQs

### 4.1 Pre-generated FASTQs (recommended)

**Simulated reads** (1,000,000 paired-end reads per layout) and **real
sequencing** FASTQs are deposited on Zenodo
([10.5281/zenodo.24366834](https://doi.org/10.5281/zenodo.24366834)).
File names are listed in [`docs/ZENODO.md`](docs/ZENODO.md).

| | Full-density Dual / Greedy / Zipcodes | Dual half density |
|--|---------------------------------------|-------------------|
| Error regime | high: 3% sub / 15% ins / 14% del | medium: 4% / 5% / 14% |
| Read form | bare 36-nt barcodes (no handles) | same |
| Source barcodes | printed layouts only (no decoys) | same |

Real sequencing: demultiplexed MiSeq paired-end FASTQs for Dual, Greedy +
2-OPT, Zipcodes (full density) and Dual half density (checkerboard).

**This `manuscript` branch does not ship the simulation code.** Download the
Zenodo FASTQs to reproduce decoding and downstream analyses.

> Note: the `simulation/` directory on branch `main` is for the separate NN≈8
> redesign experiments (different layouts and a different error channel). Do
> **not** use it to regenerate the manuscript Press-model reads below.

### 4.2 Regenerate simulated reads (optional)

Paper simulations used the Press et al. error model as implemented in
[RandomBarcodes](https://github.com/whpress/RandomBarcodes) (`makeerrors`).
The same scripts are vendored in the companion pipeline:

[BarcodeCalling_benchmark `bin/press/`](https://github.com/OncoRNALab/BarcodeCalling_benchmark/tree/main/bin/press)
(`scripts/2_SimGen_split.py` + `RandomBar_Functions.makeerrors`).

Inputs are the printed barcode lists (one sequence per line) from this branch:

| Layout | Barcode file |
|--------|--------------|
| Dual full | `data/1in1/layout_235x363_dual_4x4.txt` |
| Zipcodes | `data/1in1/layout_235x363_zipcodes_nosep.txt` |
| Greedy + 2-OPT | `data/1in1/layout_235x363_randombarcodes_opt.txt` |
| Dual half | `data/1in2/layout_1in2_dual_4x4.txt` |

Typical Press / RandomBarcodes settings used for the paper:

| Parameter | Full density | Dual half |
|-----------|--------------|-----------|
| `Q` (reads) | 1_000_000 | 1_000_000 |
| `srate` / `irate` / `drate` | 0.03 / 0.15 / 0.14 | 0.04 / 0.05 / 0.14 |
| `nave` | 4 (Poisson draws per sampled barcode) | 4 |

Workflow sketch (after installing RandomBarcodes or using `bin/press/` from
BarcodeCalling_benchmark; see that repo’s `BENCHMARK_README.md`):

1. Build or load a pickle of the printed barcode list (`N` = number of lines,
   `M` = 36).
2. Run `2_SimGen_split.py` with a YAML config setting `Q`, `nave`, and the
   rates above; write reads + answer indices.
3. Convert the plain-text read list to paired FASTQ (R1 = read; R2 =
   reverse-complement of R1) if your decoder expects FASTQ — the Zenodo
   files are already in that form.

Exact seeds and intermediate pickle paths from the original runs are not
committed here; regenerated reads will match the error model and rates but
will not be byte-identical to Zenodo unless the same seed and sampling
stream are reproduced. Prefer the Zenodo deposit for manuscript-identical
inputs.

## 5. Decode FASTQs with QUIK

Paper decoding used **QUIK only**, via the companion Nextflow pipeline
[BarcodeCalling_benchmark](https://github.com/OncoRNALab/BarcodeCalling_benchmark)
(`--tool quik`; do not run RandomBarcodes or Columba for manuscript
reproduction).

Full step-by-step instructions, the layout × threshold matrix, and example
params JSON files:

→ **[`docs/decode/README.md`](docs/decode/README.md)**

Summary:

```bash
git clone https://github.com/OncoRNALab/BarcodeCalling_benchmark.git
cd BarcodeCalling_benchmark

# Real Dual full density, r = 7 (edit paths)
nextflow run main.nf \
  --tool quik \
  --barcode_file /path/to/BarcodeLayoutOptimization/decoys/output/dual/dual_whitelist_real_plus_decoys.txt \
  --r1_fastq /path/to/zenodo/26_018_S1_L001_R1_001.fastq.gz \
  --r2_fastq /path/to/zenodo/26_018_S1_L001_R2_001.fastq.gz \
  --sample_id 26_018_S1_quik \
  --barcode_start 10 \
  --barcode_length 36 \
  --strategy 4_mer_gpu_v4 \
  --distance_measure SEQUENCE_LEVENSHTEIN \
  --rejection_threshold 7 \
  --data_mode real \
  --outdir results/dual_full_r7 \
  -profile local,singularity
```

| | Real sequencing | Simulated |
|--|-----------------|-----------|
| `barcode_start` | `10` | `0` |
| Whitelist | `decoys/output/*/…whitelist_real_plus_decoys*.txt` | same |
| `r` full density | `{5, 6, 7}` | `{5, 6, 7}` |
| `r` Dual half | `{6, 7, 8}` | `{6, 7, 8}` |

Or use a params file from `docs/decode/params/` (replace `/ABS/PATH/...`):

```bash
nextflow run main.nf \
  -params-file /path/to/BarcodeLayoutOptimization/docs/decode/params/dual_full_real_r7.json \
  -profile local,singularity
```

## 7. Key parameters

| Parameter | Value |
|-----------|-------|
| Array size | 235 × 363 = 85,305 spots |
| Barcode length | 36 nt |
| Synthesis order | A > C > G > T |
| Bit mapping | 00→A, 01→C, 10→T, 11→G |
| Dual block size | 4 × 4 |
| Dual random seed | 42 |
| Greedy input pool | 150,000 unique 36-nt barcodes (homopolymer ≤ 3, G ≤ 25%) |
| Zipcodes random seed | 42 |
| Zipcodes soft targets (bits) | 2, 4, 6, 8 at offsets 1–4 |
| Zipcodes hard min (bits) | ≥ 8 at offset ≥ 5 |
| Decoy φ (Dual, Greedy) | 1/3 (global) |
| Decoy φ (Zipcodes) | 1/3 (local, per axis) |
| QUIK strategy | `4_mer_gpu_v4` |
| QUIK threshold r | {5, 6, 7} full density; {6, 7, 8} half density |
| QUIK `barcode_start` | 10 (real); 0 (simulated) |
